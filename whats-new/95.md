- **skill-bundles:** A project can use another Catalog than the default one of the computer. Write `catalog: owner/name` in its `skills.yaml`. The mod uses a clone of that Catalog, and it never reads or changes a project with the clone of another Catalog.
- **skill-bundles:** The settings have a table, **Your own clones of other Catalogs**: the name of a Catalog and the folder of your own clone of it. **Your own clone** and **Clone URL** are now of the default Catalog.
- **skill-bundles:** In a project without `skills.yaml`, **Use Bundles** shows the Catalogs of your settings when there is more than one. The mod writes `catalog:` when you choose a Catalog that is not the default one.
- **skill-bundles:** `link-skills.mjs` in a terminal stops when `skills.yaml` names a Catalog that is not the one of the clone.
- **mods-hub:** The **Settings** tab has a new field type, a table of names and folders (`folder-map`), for the mods of the kit.
- **skill-bundles:** A repository of skills without a `bundles.yaml` can become a Catalog. Add your clone to the table, choose it in **Use Bundles**, and click **Create bundles.yaml**. The mod writes the file with an empty `core` Bundle and shows the skills, so that you can put each one in a Bundle.
