- **skill-bundles:** Skills are now links, not copies. Each project gets a directory junction (Windows) or a symbolic link (macOS, Linux) for each skill, which points to one clone of your Catalog: your own clone (setting **Your own clone**), or the clone of the mod. A change in the clone shows in every project at once. The mod no longer uses `npx skills`, and the states Outdated and Unchecked are gone.
- **skill-bundles:** The first action in a project changes the copies that `npx skills` installed to links. A copy with your changes moves to `.agents/skills-backup`. A folder that Git tracks, or a skill folder that you wrote with the name of a Catalog skill, shows as **Conflict** and changes only with **Replace by link**.
- **skill-bundles:** The links are hidden from Git in `.git/info/exclude`, one line for each link. The mod does not write `.gitignore` anymore. In a project with the old `.gitignore` block, the panel shows **Remove the old block**.
- **skill-bundles:** A toast offers to make missing links and to remove stale ones (a new worktree, a skill that left a Bundle). The mod never changes a project without a click. **Update all** is now **Link all**.
- **skill-bundles:** Your own clone with changes that are not committed no longer stops the mod: the projects see the clone as it is, and the panel only says why it cannot pull.
- **skill-bundles:** New: `link-skills.mjs`, one Node file that links a project from a terminal (`node <clone>/link-skills.mjs`). Copy it to your Catalog for people without Herdr.
- **skill-bundles:** Not supported in this version: skills of repositories that are not the Catalog (**Another repository** is gone for now, and such skills show as "Not supported yet"), and projects in spaces on other machines (the panel shows a message). Both come back in later versions.
