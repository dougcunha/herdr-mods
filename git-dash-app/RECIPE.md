# Git Dash

A Herdr app mod. It is a side panel (or a tab) that shows the pending work of every Git repository under one or more base folders: unpushed commits, staged, modified and new files, stash, conflicts, operations in progress and merged branches that were not deleted. It lists the repositories that need attention first.

No preview image ships with this recipe: a real screenshot would show private repository names.

## What you see

A card with a 1 px border, 10 px radius and the theme `background`, filling its block. From top to bottom:

1. **Header**, 40 px high. A `repos.svg` icon in `accent`, the title **Git Dash** in semibold, in `dim` (11 px, truncated) the name of the only base folder or `N folders`, and 3 square 28 px icon buttons: Fetch (`download.svg`), Folder (`folder.svg`) and Refresh (`refresh.svg`). Fetch and Folder have an accent wash when they are on (Folder: while the folders view shows). Refresh shows an accent `spinner.svg` while it works.
2. **Summary line**, 11 px, `dim`: `111 repositories · 5 with pending` on the left; on the right `N folder(s) not found` in `blocked` (only when a base folder cannot be read; a click shows the folders view), then `Scanning folders…`, then `Analyzing 22/111` in `accent`, then `Updated 3m ago`.
3. **Filter box**, 34 px, `raised` background, with a magnifier, the typed text and a clear button. The right side shows `shown/total` while text is typed.
4. **Chips**, wrapping: **Pending** (yellow dot), **Clean** (green dot), **Errors** (red dot, only when there are errors) and **All**. Each chip has a count badge. **Pending** is on at start.
5. **List**, scrolling, with a 1 px top border. Each repository is a card with a 1 px bottom border:
   - Row 1: an 8 px dot colored by severity, the path of the repository relative to its base folder (13 px semibold, truncated), and a `▸` or `▾` when it has changed files. With 2 or more base folders, the path starts with the name of the base folder (`Projetos/api`; the folder itself shows only that name). When 2 base folders have the same last part, the name is the last 2 parts (`D:/Projetos`).
   - Row 2, indented 16 px, wrapping 20 px pills: the branch (`branch.svg`, monospace), a neutral `worktree` pill when the folder is a linked worktree, then `merge in progress` (and `rebase`, `cherry-pick`, `revert`, `bisect`) and `N conflicts` and `N unpushed` in red, `N staged` in green, `N modified` in yellow, `N new` in cyan, `N stash` in magenta, `↓N behind` in blue, `N merged` (`branch.svg`) in blue.
   - Row 3, 11 px `dim`, only when needed: notes joined by ` · `: `No remote`, `Branch has no upstream`, `Upstream branch was removed`, `Detached HEAD with N unpushed commit(s)`, `↑N ahead of upstream`, `Other branches: x (2), y (1)`, `Fetch failed`.
   - Expanded: up to 12 rows of `state  path` (state in monospace: `UU` red, `??` cyan, a staged code green, an unstaged code yellow) and `… N more file(s)`.
   - Expanded, below the files, the **fix area** (indented 16 px, clicks stop there so the card stays open):
     - `Resolve by hand: …` in yellow (11 px), when `fixes(r).manual` is not empty.
     - A row of 24 px buttons (`smallButton`): the safe fixes in accent (**Commit**, **Push**, **Pull**, **Publish to origin**), then **Terminal** (`terminal.svg`) and **New space**.
     - When the repository has merged branches: a 1 px top border, the line `Merged into origin/main, not deleted:` (11 px `dim`) with a red **Delete all N** button on the right (only for 2 or more), then 2 lines per branch. Line 1 (22 px): `branch.svg` in blue, the name in monospace, an accent `current` pill for the checked-out branch, a neutral `worktree` pill for the branch of a linked worktree. Line 2 (24 px, indented 19 px): `local` or `local + origin` in `dim`, and on the right a red **Delete** button (**Remove worktree** for a worktree branch; its tooltip names the worktree folder). When the delete must wait, the row shows the reason in yellow instead of the button: `finish the operation first`, `commit or stash the changes first`, `the worktree is locked` or `close the terminals in this folder first`.
     - After a click on Push, Pull, Publish or a delete: a `raised` box with `Run this command?`, the commands in monospace and **Run** / **Cancel**. **Run** is red for a delete.
     - After a click on Commit: a `raised` box with a message input, 1 to 3 mode buttons (**Staged only**, **Tracked files**, **All, with new files**; the last one red with a warning line), the commands in monospace and **Commit** / **Cancel**.
     - While a fix runs: a spinner and `Push · Running…`.
     - The result: a green `Done.` or a red `Failed.` box with the last 4 output lines, and **Run in terminal** on a failure.
6. **Empty states**: no folder: a tile with the icon, the title *Choose a folder with your repositories*, a hint and a primary **Choose folder** button. No repository in the folders, or an error (no base folder can be read): the message, the folders (native slashes, `~` for home, joined by `, `), a primary **Add folder…** button and a **Folders** button.
7. **Folders view** (the Folder button, or the `folders` command), in place of rows 2 to 6: the title `Repository folders` (13 px semibold) and `Git Dash looks for Git repositories in each folder, up to 4 levels deep.` (11 px `dim`), then, with a 1 px top border, one 40 px row per base folder with a 1 px bottom border: `folder.svg` (15 px, `accent`, or `blocked` when the folder cannot be read, with the error as tooltip), the path (12 px, native slashes, `~` for home, truncated), a pill `12 repos` (`…` while the search runs) or `not found` in `blocked`, and a 28 px `trash.svg` icon button. Below: a primary **Add folder…** button and **Back to the list** (only with 1 or more folders).

Severity (dot color and sort order, highest first): 5 conflicts or an operation (red), 4 unpushed commits (red), 3 staged or modified (yellow), 2 new files only (cyan), 1 stash or merged branches only (magenta), 0 clean (green). An error repository has a red dot, shows its error line and no pills. Ties sort by path.

## How it behaves

- Start: the base folders are `shared("git-dash.roots")`, one list for every copy of the panel: an array of paths with forward slashes, no trailing slash (except a drive root such as `D:/`), no duplicates (compared with `samePath`). When the key is not an array (it was never saved), the mod builds it once from the folder of older versions, `shared("git-dash.root:<root>")` for a copy with a `root` prop, else `shared("git-dash.root")`, else the `root` prop, and saves it. The old keys are never written. A saved empty list stays empty. With no folder, the panel shows the empty state. Fetch starts from the `fetch` prop, else `shared("git-dash.fetch")`.
- The mod finds the repositories of all base folders at the same time (one `findRepos` per folder), then analyzes 12 at a time. A folder that cannot be read goes in `rootErrors` and does not stop the others; only when every folder fails does the panel show the error. A repository that two base folders hold (one folder inside the other) shows once, under the first folder. Each result keeps its `root`. Cards appear while the run goes on. On a refresh the old cards stay until their new data arrives; repositories that vanished are removed at the end.
- **Add folder…** opens `pickFolder`. A folder that is in the list already shows an `info` toast. A new folder is added at the end, the list is saved with `setShared`, the cards are cleared and a run starts. A run of the old list that ends later is ignored (a generation counter).
- The trash button removes a folder and saves the list. While no run is active, only the cards of that folder go away, with no new search. During a run, the cards are cleared and a run starts.
- A 1 s timer compares `shared("git-dash.roots")` with the list of this copy. When another copy (or the mods-hub) changed it, the copy takes the new list, clears the cards and starts a run.
- Commands (`nextCommand()`): `folders` shows the folders view, `list` shows the repositories, `refresh` starts a run.
- **Refresh** does nothing while a run is active. A 30 s timer re-renders the *Updated* age, and starts a silent run when the data is 5 minutes old.
- A card with changed files, a fix, a pending item, an error or a fix result toggles on click. A clean card does nothing.
- **Fixes** (`fixes(r)` in `git.js`) split into `auto` and `manual`. Conflicts, an operation or a detached HEAD block all `auto` fixes. Otherwise: dirty files give `commit`; with an upstream, ahead only gives `push`, behind only gives `pull` (`--ff-only`), ahead and behind is `diverged` (manual); an upstream that is gone is manual, unless the checked-out branch is in the merged list (its delete is the fix); no upstream with commits on the branch gives `publish` to `origin` (or the only remote). No remote, stash and other branches with commits are manual.
- **Merged branches** (`fixes(r).merged`, one entry per branch with `fix` or `blocked`): a conflict or an operation blocks every delete (`busy`); staged or modified files block the delete of the checked-out branch (`dirty`). For the branch of a linked worktree: a locked worktree gives `locked`, staged, modified or new files in it give `dirty`, and a Herdr terminal whose `panes()[i].cwd` is the worktree folder or inside it gives `inUse`. Each fix has `cwd` (the main worktree when the card is a linked worktree, else null) and `removes` (the worktree folders that its `worktree remove` step removes; empty for a prunable worktree, which has no card). **Delete all N** runs the steps of every branch that is not blocked, one branch after the other, the checked-out branch last.
- Only one card at a time asks (`this.ask`). The commit mode starts at *staged* when something is staged, else *tracked*, else *all*. An empty message does not commit.
- A fix runs with `runSteps` (`exec("git", ...)` in `fix.cwd` or the card folder, one step after the other, stop at the first failure; `done` counts the steps that ended well), then `refreshOne` reads the repository again: `findRepos(path, 0)` for its operations, then `analyze`. When a `worktree` step ended well (`removedBy`), the cards of the removed folders go away. When the card itself was removed, `notify` shows `Worktree removed` (success) or `Worktree removed, but a later step failed` (warning, with the Git output), and the card of the main worktree is read again.
- **Terminal** runs `tab.new {name, folder, argv: ["git","status"]}`; **New space** runs `space.new` with the same arguments. **Run in terminal** uses `argv: ["git", ...failedStep]`. The shell stays open after the command. Then `refreshOne` runs after 20 s, 90 s and 5 min.
- Languages: `en` and `pt` dictionaries in `main.js`.

## Built from

Files in `mods/git-dash/`: `mod.json` (`{ "place": "none" }`, written first), `main.js` (the `View`), `git.js` (search and analysis), `ui.js` (pills, chips, buttons, small card buttons, search box) and the icons `repos`, `refresh`, `folder`, `download`, `search`, `close`, `branch`, `spinner`, `terminal`, `trash` (`.svg`, 24 px, stroke `currentColor`).

- **Search** (`findRepos`): runs `pwsh -NoProfile -NonInteractive -Command <script>` on Windows, `sh -c <script>` with `find` elsewhere. It walks `depth` levels (default 4), skips the folders in the `SKIP` list and reparse points, does not enter a repository's `.git`, stops at 400 repositories, and prints `path<TAB>marker,marker` per repository. The markers are the files `MERGE_HEAD`, `rebase-merge`, `rebase-apply`, `CHERRY_PICK_HEAD`, `REVERT_HEAD` and `BISECT_LOG` inside the Git folder (a `.git` file with `gitdir:` is followed). A missing folder gives exit code 2 and a message on stderr.
- **Analysis** (`analyze`): `git --no-optional-locks -c core.quotepath=false status --porcelain=v2 --branch --show-stash --ignore-submodules=dirty --untracked-files=normal` gives branch, upstream, ahead and behind, stash count and files. Type `1` or `2` lines count as staged when `X` is not `.` and as modified when `Y` is not `.`; `u` is a conflict; `?` is new. `git remote` runs only when there is no upstream. `git log --branches HEAD --not --remotes --source --format=%S` gives the unpushed commits by branch (skipped without a remote or in a repository with no commit). `git fetch --all --prune --quiet` runs first when fetch is on.
- **Merged branches** (`findBase` and `findMerged`, skipped in a repository with no commit): the base is the target of `refs/remotes/origin/HEAD`, else the first of `refs/remotes/origin/main`, `refs/remotes/origin/master`, `refs/heads/main` and `refs/heads/master` that `rev-parse --verify` accepts. `for-each-ref refs/heads refs/remotes` with `%(refname) %(objectname) %(HEAD) %(worktreepath) %(upstream) %(upstream:track) %(upstream:remotename) %(upstream:remoteref)` gives every branch, and `for-each-ref --merged=<base>` gives the merged ones. A merged local branch counts unless: its name is in `PROTECTED` (`main master develop development dev trunk staging production release`) or is the base; it is checked out in the main worktree and this card is a linked worktree; its remote copy (its upstream, else `<remote>/<same name>`) exists and is not merged. An upstream that is the base or a protected branch is not a remote copy (a branch made with `git switch -c x origin/main`), and the panel never deletes it. A branch with no upstream counts only when `git reflog show --format=%gs` has an entry that is not `branch: Created from…` (an empty reflog counts). At most 20 branches and 40 reflog reads per repository.
- **Worktrees** (`listWorktrees`): `git worktree list --porcelain` gives `worktree <path>`, `branch <ref>`, `locked` and `prunable` per worktree, the main worktree first. A card whose folder is not the first one is a linked worktree: `r.worktree = { main }`. A merged branch that a linked worktree has checked out gets `worktree: { path, locked, prunable, dirty }`; `dirty` comes from `git -C <path> status --porcelain --untracked-files=normal --ignore-submodules=dirty` (not run for a prunable worktree).
- **Delete steps** (`deleteSteps`): `merge-base --is-ancestor refs/heads/<b> <base>`; with a remote copy, `push <remote> --delete <b> --force-with-lease=refs/heads/<b>:<sha of the remote copy>`; for the checked-out branch, `switch <local base>`; then `branch -D <b>`. A worktree branch has `worktree remove <path>` (or `worktree prune` when the folder is gone; prune cleans every prunable worktree of the repository) right after the ancestor check, and no `switch`. The ancestor check and the lease replace the check of `branch -d`, which compares with the upstream or `HEAD`, not with the base.
- A repository is *pending* when it has unpushed commits, stash, staged, modified, new files, conflicts, an operation, merged branches, no remote, or is ahead of its upstream by more than its unpushed count.
- `herdr` functions: `exec`, `home`, `theme`, `props`, `shared`, `setShared`, `pickFolder`, `run`, `panes`, `notify`, `nextCommand`. `gpui-base`: `InputState` (its `submit` event commits), `Input`. Native animation only: `svg(...).spin(900)`.

## Watch out

- A mod reads files only inside the Herdr home (`fs/promises` throws *outside every granted read root*). Do not walk the base folder with `fs`: use `exec`.
- In PowerShell, `@($a, $b + 1)` is a 3 item array, because the comma binds tighter than `+`. Compute `$next = $level + 1` first, or the depth limit never works.
- PowerShell hashtable keys are case-insensitive, so `Build` and `bin` skip too. The Python original is case-sensitive. This is a deliberate small difference.
- `exec` cannot set environment variables, so `GIT_OPTIONAL_LOCKS=0` becomes the flag `--no-optional-locks`. Porcelain v2 output does not depend on the locale, so `LC_ALL` is not needed.
- `exec` has a 30 s limit and gives the program no input. `props()` can answer for another copy: read the props once in `init(given, cx)`.
- Pass props to `tab.new` from PowerShell through a variable: `$p = '{"root":"D:/Projetos"}'`, then `--props $p`. Forward slashes avoid JSON escapes.
- A hot reload of the mod closes the tabs that show it. A `main.js` save restarts the scan.
- `--force-with-lease` also guards a `push --delete`: with a stale expected value the push fails with `(stale info)`. Put it after the branch name, so the truncated command line in the confirmation still shows the remote and the branch.
- `flex_shrink` needs a number: `flex_shrink()` with no argument breaks the render. Use `flex_shrink_1()`.
- The `root` prop is only a first guess, used once when `git-dash.roots` was never saved. To test a list of folders from the shell, set `git-dash.roots` from a throwaway mod (write its `mod.json` first) and run `herdr-app do git-dash.folders`; the copies follow the new list within 1 s.
- Do not strip the trailing slash of a drive root: `D:` alone is the current folder of drive D in PowerShell, not its root.

## Done when

- `herdr-app check ~/.config/herdr-app/mods/git-dash` passes.
- With `root` set to a folder of repositories, the panel scans, shows `Analyzing n/m`, then `Updated just now`.
- The **Pending** list equals the repositories that `git-pendencias.py <folder> --json` marks `pendente`, with the same counts, and the repository total equals its `repositorios` length.
- A repository with a conflict or a rebase in progress is first and red. A detached HEAD with commits that no remote has shows `N unpushed`.
- On the first start after an update from a single folder, `git-dash.roots` holds that folder and the list looks the same as before.
- With 3 base folders (2 valid, 1 missing): the header shows `3 folders`, the cards start with the folder name, the summary shows `1 folder(s) not found`, and the folders view shows `12 repos`, `0 repos` and a red `not found`. The trash button and **Add folder…** change the list, and the list survives a restart. **Refresh** spins and ends.
- In a test folder: **Push** on a repository that is ahead, **Pull** on one that is behind and **Commit** (*Tracked files*) on a dirty one each show `Done.`, and the card reads the repository again. A repository with a conflict shows only *Resolve by hand*, **Terminal** and **New space**.
- **Terminal** opens a tab in the repository folder with the `git status` output, and the shell stays open.
- With the Dock entry in `panels.json`, the **Repos** button shows next to **Changes** and **CI**, and it shows and hides the panel.
- In a test repository with a bare remote: a fast-forward merged branch with its remote branch shows `local + origin`; a merged branch whose upstream is gone and a merged branch with no upstream show `local`. A new branch with no commits, a branch made from `origin/main`, `develop`, an unmerged branch and a merged branch whose remote copy has 1 more commit do not show. **Delete all** removes the branches here and on the remote, and the card reads the repository again.
- In the same test repository with 4 linked worktrees: a merged and pushed worktree, a merged worktree with a new file, an unmerged worktree, and a merged and locked worktree. The unmerged one does not show. **Remove worktree** in the card of the merged worktree removes the folder, the remote branch and the local branch. The other 2 rows show `commit or stash the changes first` and `the worktree is locked`. A worktree whose folder was deleted runs `git worktree prune`.
- `herdr-app status` shows `"errors": []`.
